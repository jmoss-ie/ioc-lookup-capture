IOC Lookup Capture — Options

File naming

With this on, each Capture run also saves manifest-<time>.json (each screenshot's indicator, site, file, size, capture time and SHA-256) and SHA256SUMS-<time>.txt (the same hashes, in the format sha256sum -c checks) in the case folder. With it off, only the screenshots are saved.

chrome.downloads can only write inside the browser's Downloads directory — that's a hard Chromium limit, not a design choice here.

Query evidence

Two popup actions that save numbered files into the case folder, in the order they were made: Capture section screenshots part of the current page (the Sentinel query and results, by default), and Rename exports, while switched on, renames files that web pages download — a Sentinel or Defender query export, for example. Both use the template below. Downloads started by other extensions are never touched.

Tokens: {prefix} (the Prefix above) {case} {seq} (01, 02, … per case) {label} (optional, typed in the popup; kept until you change it) {name} (the name the site gave the file) {timestamp} {date}. An empty token is dropped together with one separator next to it. The file's original extension is always kept.

A download matches if the tab you're looking at when it starts, the page that created it, or the page it was started from is on the list. The easiest way to fill this in: export once with the filter off, then press "Only rename from …" in the popup, which adds that export's sites and switches the filter on.

Window behavior

"Open for review" in the popup always leaves its windows/tabs open, regardless of "Keep windows open" — that's the point of that action. "Keep lookups in my current window" opens new background tabs in your own window rather than your active tab; it never closes or replaces that window itself, only the tabs it opened. Combined with "Open lookups in the same window," one tab in your window is reused for the whole batch; without it, each lookup gets its own new tab there. A site's "Fullscreen" option, combined with this setting, maximizes your whole browser window (restored afterward) rather than a separate one. With the viewport and stitched backends, each capture briefly makes its tab the active one in your window (and restores whichever tab was active before) — the full-page (debugger) backend doesn't need to do this.

"Fullscreen" maximizes the capture window for that site before capturing — it does not click an in-page fullscreen button. Some sites (maps, dashboards, graphs) render more detail given more screen space.

"Bot check" — Wait if shown: while the page settles, the capture watches for a Cloudflare check or a captcha. If one shows, it waits until the check has gone, then lets the page settle again; if it's still there after a few seconds, the lookup window is brought to the front so you can solve it. Always pause: for a site whose captcha you have to complete every time and which stays on the page afterwards (tick it, press the site's own button): after the page settles, the window is brought to the front and the capture waits for you to press Capture now in the popup.

While a capture waits, the toolbar icon shows WAIT, and the popup (open it again if it closed when you clicked into the lookup window) has Capture now and Skip. If neither the check nor you end the wait within the limit under Timing, that lookup fails rather than saving a screenshot of the check. Use "Wait if shown" only for sites that show checks: one with a captcha on its normal page would wait every time.
