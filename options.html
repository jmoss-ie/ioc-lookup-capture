IOC Lookup Capture — Options

File naming

chrome.downloads can only write inside the browser's Downloads directory — that's a hard Chromium limit, not a design choice here.

Example:

Query evidence

Two popup actions that save numbered files into the case folder, in the order they were made: Capture section screenshots part of the current page (the Sentinel query and results, by default), and Rename exports, while switched on, renames files that web pages download — a Sentinel or Defender query export, for example. Both use the template below. Downloads started by other extensions are never touched.

Tokens: {prefix} (the Prefix above) {case} {seq} (01, 02, … per case) {label} (optional, typed in the popup; kept until you change it) {name} (the name the site gave the file) {timestamp} {date}. An empty token is dropped together with one separator next to it. The file's original extension is always kept.

Each entry also covers its subdomains. A download matches if the page that created it, or the page it was started from, is on the list. The popup shows recently skipped downloads and the sites they came from, so you can add the right one.

Window behavior

"Open for review" in the popup always leaves its windows/tabs open, regardless of "Keep windows open" — that's the point of that action. "Keep lookups in my current window" opens new background tabs in your own window rather than your active tab; it never closes or replaces that window itself, only the tabs it opened. Combined with "Open lookups in the same window," one tab in your window is reused for the whole batch; without it, each lookup gets its own new tab there. A site's "Fullscreen" option, combined with this setting, maximizes your whole browser window (restored afterward) rather than a separate one. With the viewport and stitched backends, each capture briefly makes its tab the active one in your window (and restores whichever tab was active before) — the full-page (debugger) backend doesn't need to do this.
